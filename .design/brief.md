# Protest Atlas design brief

Product: a public, source-led index of collective action, hosted as a static GitHub Pages site. Release 4.0 (built and verified locally on 3 Oct 2026; deployment pending) is a mobile-first rebuild of the interface over the release-3 data. The binding design is `docs/design/SPEC.md`; this brief keeps the direction and the invariants.

Primary job: on a phone first, read dated, source-checked reports of protest activity, see how old the newest evidence is, filter by country, issue, region, status, city, year, outcome and observed date, and open a record to inspect attributed positions toward named targets, intensity, state response, outcome and the original reporting. Secondary jobs: see published coverage on a country map, browse all 249 countries and territories, read announced protest actions kept apart from reports, and see what the atlas itself is building next. A separate local editor desk prepares draft decisions from unverified news leads.

Audience: curious readers, journalists and researchers who need to tell reported activity apart from uncertain or missing coverage, mostly on phones.

Direction: a reports desk with atlas components. Five views (Reports, Map, Ahead, Countries, About) in a bottom tab bar under 900 px and a header nav above it; records open in a sheet. Warm paper, deep ink, restrained ochre for published coverage, serif titles, compact sans-serif evidence labels, ruled rows. Cards lead with status, then place, title and latest-evidence date, then compact facts (timeframe, for/against with its target, intensity, police/state) and the first source. A compact List layout serves scanning. The map is a functional D3 Equal Earth coverage map; color describes published reporting coverage, never intensity, popularity or a worldwide census. Country labels use short common names for display while the data keep ISO names.

Evidence: source links with publisher and publication date, latest source re-read, newest evidence date, verification notes, attribution, UTC dates and explicit unknowns. Each update stamp names its own subject (snapshot assembled, AI-assisted review pass (only when it differs from snapshot assembled; it does not appear in this snapshot), newest evidence, latest source re-read, announced-actions list compiled, site built, lead-discovery audit, human editorial review "Not completed") and they are never merged into one "updated" time. The snapshot has 84 episodes across 81 countries, 118 city references and an initial search for every one of the 249 directory entries; 168 countries have no published episode. Initial searches are separate from article-level source checks. Black shadows mean a sourced ended/suspended episode, never completed country research. The pilot is AI-assisted with no independent human editorial review; that disclosure is above the content of every view. Discovery status is a dated static audit of a known artifact, never a live-health indicator. The 2 Oct recent-activity search could not open any news page, so nothing newer is published and the announced-actions list is empty; the interface says so.

Constraints: static HTML/CSS/JavaScript ES modules with a store and hash router, no framework, bundler or build-time minifier. Pinned local D3 7.9.0, TopoJSON Client 3.1.0 and world-atlas 2.0.2/Natural Earth assets, loaded only when Map is first opened; the runtime reads the TopoJSON and a code table, not a GeoJSON. No mapping token, remote tiles, runtime CDN or web fonts. Python validates and assembles an explicit publication allowlist; relative paths work under a GitHub Pages repository base path. No geolocation, analytics, accounts, identification of individual participants or invented metrics. Synthetic examples require an explicit switch, a clear watermark on card, record and map, and exclusion from counts, the directory and CSV export. Measured payload ceilings in CI; code and data budgeted apart.

Invariants: zero records is a useful coverage-gap state; zero matching results is not evidence of no protests. Map, brief, Reports and CSV use the same filters; a country with reports outside the current filters differs from one with no published record. Observation presets and grouping use `last_observed_at`, never publication, discovery, build or deploy time. Ongoing statuses age against that observation and become Needs review at 72 hours; the snapshot is aging after 72 hours, stale from 7 days and archive from 30, counted from the newest evidence. Once stale, no record is labelled "latest" or "new". Future start dates remain Planned. Unknown onset stays unknown. "Not established" is never shown as zero, none or blank. Turnout, disruption, violence and state response are separate dimensions with no combined score. For/against always names a target; positions are never tallied. Announced actions are never occurrences, carry no times, meeting points or routes, and a passed date reads "occurrence not established". Sources remain attached to claims. A failed file reads as unknown, never as empty, and offers Retry. Filter permalinks reproduce the view; CSV retains source URLs, recorded-status uncertainty and formula escaping. Roadmap items carry no dates; "shipped" means checked on the deployed site.

Responsive composition: phones (360–390 px) are primary. The first viewport holds the header and snapshot chip, the disclosure, the snapshot facts, search and filters, and the start of the first record, in every snapshot state. From 600 px a 720 px Reports column (centred to 899 px, left-aligned from 900); from 900 px header navigation and drawer sheets; from 1200 px a sticky side rail on Reports. Short viewports (landscape phones, 200 % zoom) let the header scroll away, shrink the tab bar to 48 px and use full-viewport sheets. On the map one finger scrolls the page until Explore is turned on; pan and zoom controls and the Countries list supplement pointer interaction. Map failure cannot block Reports; small territories omitted by the 1:110m geometry remain selectable through Countries and the country filter. Sheets use native dialogs with explicit close, initial title focus, Escape and focus restoration.

Editor desk: import candidate JSON using a local file input, search provider metadata, read source links and enter evidence manually. Work stays in tab memory and exports only a local JSON review packet. Publisher country and GDELT seen time must never fill occurrence fields. "Ready for editor" requires source acknowledgement, nonfuture observed date, catalog country, claim summary and attribution; duplicate decisions need a published event ID. Draft readiness is not approval, enrollment of a human reviewer or automatic publication. No account, local storage or remote submission is part of this desk.
