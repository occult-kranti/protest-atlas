## Questions the panel must answer
1. What may hot/cold honestly encode? Candidates: recency of newest evidence (72 h / 7 d / 30 d / older bands already exist as observationBand), or nothing (reject). If recency: sequential one-hue ramp vs diverging two-pole with neutral midpoint — decide with the validator, explain the legend copy, default state (coverage-only) and the control ("Colour by").
2. Kind taxonomy for events: e.g. protest/demonstration, strike/industrial action, civil unrest (riot, violent demonstration, communal violence), armed conflict — intrastate, armed conflict — interstate. Cite definitions (UCDP: state-based armed conflict ≥25 battle-related deaths/yr; war ≥1,000; type_of_conflict interstate/intrastate/internationalised; non-state; one-sided). How do the 84 existing records get a kind honestly (pipeline default from the research contract, not keyword guessing)? What colour/pattern per kind under the all-pairs cap (≤3 hues + textures)?
3. Data model for conflicts: extend events.json with `kind` (and conflict-specific fields?) or a separate `public/conflicts.json` with its own schema (parties, type, UCDP ids, fatality estimates with source + range, start, latest evidence) and validator? Separate avoids weakening the protest schema and lets the data session work independently. Decide.
4. UI: where the encodings appear (map fill, map legend, card badge, record sheet, filters "Kind" chip), patterns in SVG (`<pattern>` defs) and CSS (card stripes), forced-colors behaviour, dark mode, print.
5. Honesty: how to avoid "war map" sensationalism; what "ongoing" means for conflicts (UCDP active-year basis vs our 72 h rule); fatality numbers must be ranges with source; no live-casualty framing.
6. Roadmap items and statuses; data handoff additions for the news-access session (UCDP download → `scripts/ingest_ucdp.py` offline from a downloaded CSV; civil-unrest sourcing rules).
